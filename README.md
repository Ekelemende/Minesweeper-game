# Minesweeper: ветка `optimization`

В этой ветке (`optimization`) первый коммит содержит ту же исходную версию игры, что и в ветке `original-version` а дальше каждое улучшение вносится отдельным коммитом.

## Оптимизация 1. Backtracking в `bruteForceRec` (алгоритмическая)

### Проблема
Продвинутый бот, когда простых правил не хватает, перебирает все расстановки мин на границе открытых клеток (неоткрытые клетки рядом с цифрами) и по ним считает вероятность мины для каждой клетки. Исходная функция `bruteForceRec` перебирала все 2^k вариантов и проверяла ограничения только в конце. Из-за этого время росло экспоненциально, а на саму функцию приходилось 80.3% времени работы программы.

### Что изменено (`bot.c`)
Перебор заменён на backtracking с ранним отсечением. Для каждого ограничения хранятся два счётчика: сколько мин уже поставлено и сколько клеток ещё не назначено. После назначения клетки счётчики обновляются, и если ограничение уже нарушено (мин больше требуемого или оставшихся клеток не хватает), вся ветка отбрасывается, не доходя до листа.
Структура `BruteResult` заменена на `BruteState` (счётчики ограничений, список ограничений для каждой клетки, текущее назначение, число допустимых вариантов).
Функция `analyzeComponent` переписана под новую структуру. Остальной код (`solveByBruteForce`, `splitIntoComponents`) не менялся.

### Результаты
Результаты тестирования находятся в ветке `testing`

### Вывод
Время перебора из экспоненциального стало почти линейным. На малых полях (Beginner, Intermediate), где перебор запускается почти на каждом ходу, ход Advanced стал стоить почти столько же, сколько ход Simple. На Expert выигрыш небольшой, так как перебор там срабатывает редко из-за ограничения `totalUnknown <= 60`. Главное узкое место устранено.
